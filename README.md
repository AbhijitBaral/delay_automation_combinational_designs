# Automated Design Flow for performance evaluation of manually placed, parameterized Combiational circuit designs  
---

## Usage  
Once all rtl/rtl generating scripts and `flow_config` are setup, call the vivado in batch mode from the parent_flow directory, and source the `master.tcl` script, with the command `vivado -mode batch -source master.tcl`  


* Four details have to be specified in the `flow_config` file :  
**  project name
**  board part name
**  top module name
**  parameter combinations the flow is to run over  

**Setting parameter combinations**
The parameter combinations refer to the set of values of the parameters used in the design, for which the design is to be implemented and analyzed. In the *flow_config* file, the combinations are to be specified with loop structures in a syntax, similar to that of TCL syntax.  
A for loop with loop variable x is written as: `for x {x1 to xn} {stepx}`. A foreach loop is written as: `foreach x {x1, x2, x3,..xn}`. The loops are nested hierarchicaly.  

```text
for param_A {A1 to An} {stepA}
foreach param_B {B1, B2, B3, B4}
for param_C {C1 to param_B} {stepC}
:
:
```
The above will be parsed and converted to correct tcl syntax:  
```tcl
for {set param_A A1} {$param_A <= An} {incr param_A stepA} {
    foreach param_B {B1 B2 B3 B4} {
        for {set param_C C1} {$param_C <= $param_B} {incr param_C stepC} {
   		.
		:
		:
        }
    }
}

```
ex:  
```text
for param_A {8 to 16} {4}
foreach param_B {1, 2, 3}
for param_C {0 to $param_B} {1}
```
converted to:  
```tcl
for {set param_A 8} {$param_A <= 16} {incr param_A 4} {
    foreach param_B {1 2 3} {
        for {set param_C 0} {$param_C <= $param_B} {incr param_C 1} {
   		
        }
    }
}
```

**Guidelines for writing RTL/ RTL generating tcl scripts**
This flow supports delay analysis of parameterized RTL(verilog) or RTL generated by parameterized TCL scripts. The later may be necessary for projects wherein manual placement of each object is necessary with `RLOC` property set procedurally for each cell for a large number of cells.

* **Verilog RTL**
All the parameters of the design have to be passed through the module header of the top module. But they should not be initialized with any constant. They must be assigned with a variable named as: `param_<parameter_name>`.
ex:  
```verilog
module top_module #(parameter A=param_A, B=param_B, C=param_C, ...)(...){
...
}
```
The flow will recognize the parameters and set their values according to the current parameter combination.  

* **RTL generating TCL**
In case the RTL is being procedurally generated by a script (only supporting tcl currently), the verilog should be generated and stored inside a variable `gen_dump`. Each module of the design has to be generated by a unique generator tcl script, with file named the same as that of the module. Each script will be generating the Verilog and storing them inside a variable `gen_var`.  
The parameters at the start of the script have to be initialized with `param_<parameter_name>`. They will be appropriately set during the sourcing of the scripts.

ex:  
```tcl
set gen_dump ""
set N $param_N
set M $param_M

append gen_dump "\n`timescale 1ns / 1ps"
append gen_dump "\nmodule module_1 ("
append gen_dump "\n    input \[[expr {$N-1}]:0\]A,B,"
append gen_dump "\n    input Cin, clk, rst,"
append gen_dump "\n    output \[[expr {$N-1}]:0\] sum,"
append gen_dump "\n    );\n"
:
:
```
Either the verilog or tcl method is used, the files are stored inside the `rt_src_dir`

## 🧰 Function Reference

### `flow {proj_id param_dict top_module}`

Runs the entire synthesis and timing analysis flow for a specific parameter configuration.

- **Arguments**:

  - `proj_id`: Unique project identifier.
  - `param_dict`: Dictionary of parameters (e.g., N, M).
  - `top_module`: Name of the top-level module in RTL.

- **Steps**:

  1. Create project directory and project.
  2. Generate RTL sources.
  3. Add sources and set top module.
  4. Run delay characterization.
  5. Save WNS/WPWS and clean up.

### `gnspc::gen_modules {param_dict proj_id top_module}`

Generates the RTL design based on parameter values.

- Reads generator `.tcl` or `.v` files.
- Replaces parameter placeholders.
- Writes output Verilog to `design_modules` directory.

### `get_delay {proj_id}`

Sweeps clock period to find timing-violation-free minimum clock.

- Starts at an initial clock period.
- Adjusts using worst negative slack (WNS).
- Saves each iteration in summary.

The clock period corresopnding to the WNS~= 0 is found by linear interpolation of wns=0. This method of iteratively interpolating, is possible because the behaviour of WNS vs clock period for a manually placed(fixed) design is linear.  
**wns = clock_period - (Setup time + Data path Delay)**.

![fwe](https://github.com/AbhijitBaral/delay_automation_combinational_designs/blob/main/figs/wns_vs_cp_2.svg)

### `fl_rep {cp count proj_id}`

Helper for `get_delay`, performs a single synth + impl + report pass.

- Writes constraint.
- Launches synth and impl.
- Parses `report_timing_summary`.
- Extracts WNS, WPWS, TNS.

## 📝 Notes

- Make sure `rtl_src_dir` is defined and contains correct RTL generators or sources.
- `top_module`, `part_name`, and `proj_name` must be set before running.
- Results are cumulative and saved per run.
- Script is written for Vivado TCL batch flow (non-GUI).
